# 小师妹工作台体验标准 v1

这份标准约束的是“创作工作台怎么被人使用”，不是单张小红书图片怎么排版。单张成品继续由 `XHS_GRAPHIC_PRODUCTION_STANDARD.md` 约束。

## 1. 本次结论

静态 HTML 或直接生成图片容易稳定，是因为它们只有一个最终画布、一个 viewport 和一次性内容；工作台同时存在编辑态、预览态、导出态、阶段状态、草稿状态和桌面/窄屏状态。此前这些状态分别由组件、CSS、缓存和服务进程决定，没有一个“用户正在看到的完整工作台”作为最终视觉权威。

因此此前出现了三类假通过：

- 单页画布排得对，但导航、工具栏、画布和右侧面板同时争夺注意力，整机仍然难用。
- DOM 几何测试通过，但隐藏的行内元素被当成可见越界，产生错误导出告警。
- 4184 网页能打开，但 4175 生成服务未启动，界面看起来在线，核心操作实际不可用。

## 2. 工作台唯一布局原则

工作台采用“画布优先、当前任务唯一、其余渐进披露”：

- 中央画布是第一视觉层，必须占最大可用面积，不能被常驻说明或次要表单挤压。
- 顶部工具栏只放当前选中对象的局部操作，例如裁剪、版式和移动；不承载整个流程。
- 右侧检查器一次只显示当前阶段的内容。点击“原文 / 文字 / 配图 / 排版 / 发布包”时替换检查器内容，不把五个阶段纵向同时铺开。
- 每个阶段只有一个主操作。主操作之外的历史、补充要求、标签和高级设置默认折叠。
- 页胶片条只负责页面定位、增删和顺序，不承载正文摘要墙。
- 窄屏不缩放桌面三栏；默认全屏画布，工具栏和检查器使用底部抽屉。

## 3. 可用性一票否决项

- 页面能打开但生成服务离线，算不可用。
- 保存后刷新不能回到同一文章、同一页和同一版式，算不可用。
- 导出按钮可点但没有新发布包落盘，算不可用。
- 可见页面没有越界，却因为隐藏节点触发导出拦截，算不可用。
- 同一屏出现两个同等级主按钮，或右侧同时展开两个以上创作阶段，算层级失败。
- 桌面视口下中央画布不是最大的连续视觉区域，算画布优先失败。
- 窄屏依靠整体缩小三栏而不是重排为单主区，算响应式失败。

## 4. 现实验收路径

每次改工作台必须按同一条用户旅程回读：

1. 从根命令启动，确认工作台与生成服务都在线。
2. 打开真实文章，选择版式并保存。
3. 刷新页面，确认文章、当前页、版式和编辑内容仍在。
4. 检查桌面与窄屏的完整工作台，不只截中央画布。
5. 确认可见页面无裁头、重叠、越界和错误拦截；白色背景或自然白色留白不按缺陷处理。
6. 下载发布包，确认产生新的 ZIP，并回读页图、文案和 manifest。

组件测试、构建成功和局部截图只算中间证据，不能替代这条真实旅程。

## 6. 本轮固化规则

- 静态画布好看不等于工作台好用；最终权威是“生成 → 编辑 → 保存 → 刷新 → 窄屏 → 下载 → 解包”的同一真实草稿。
- 生成模型输出的网格只是像素，不是坐标合同；任何固定切片都要接受真实分隔线和主体完整性复检。
- 白背景是内容；灰线、透明边、邻格残片才是污染。不得再以“发现白色”作为裁边依据。
- 付费调用和后处理分成两个事务：先保存已付费原图，再切片；后处理升级只重放原图，不重复计费。
- 标题换行以短语为单位；窄屏需同时回读 viewport、scrollWidth 和现场截图。
- 复制、下载、保存等按钮必须回读实际结果；toast 或按钮文案不是证据。
- 智能排版只拥有默认几何，不拥有最终作品：自动版完成后，标题、正文、图片取景、图文模块位置与缩放必须继续可编辑、可保存、可撤销。
- HTML/文生图的整体构思能力通过 `design-program.v1` 接入，不让模型直接生成不可控 DOM/CSS。程序只表达构图职责、视线顺序、节奏、图像份量、方向、标题行宽和留白；当前 `html_state` 继续是唯一可编辑状态。
- 智能排版必须先看整组页面再决定单页，避免相邻内页连续使用同一节奏和同一首图方向；变化必须服务内容，不得为“看起来不模板”随机抖动。
- 内容语义拥有主次：`content_role=hero` 决定视觉主角，设计程序只能引用，不能把 support/detail 晋升为 hero。
- schema 迁移不得抹掉已有手工版式、密度、取景、文字或模块位移；旧稿只补齐缺失的设计程序。
- 封面使用同一条比例链：母版上方六格生成 9:8 KV，页面下方 2/3 消费 9:8 KV；禁止在生成、切片、显示三层重复改比例。
